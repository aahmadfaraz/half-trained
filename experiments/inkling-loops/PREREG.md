# Pre-registration: does a looped model think without words?

Written 22 Nov 2026, before any of the runs below. Changes after this commit are listed at the end, each with its date, and are made before the runs they affect.

## Model and setup
- Model: Thinking Machines' `TML-d24-varloop-research` (Apache-2.0), the variable-loop twin of Inkling 2 Mini. 24 layers; layers 6-17 run N times per token. Trained with 1-5 passes (sampled 1:2:6:2:1), post-trained at 3.
- File: `ggml-org/TML-d24-varloop-research-GGUF`, IQ4_NL (17.6 GB; the NVFP4 experts re-quantised to IQ4_NL, everything else Q8_0). This is not the native checkpoint, so absolute scores may differ from the model card.
- Runtime: llama.cpp commit `afe77e18fadc2e673c6a6299495a443e17378ce4`, built with CUDA for sm_75. Kaggle, 2× Tesla T4. Loop count set with `--override-kv inkling2_loop.loop.count=int:N`. Layers 0-11 pinned to GPU 0 and layers 12-23 to GPU 1. `-c 4096` per sequence, flash attention on.
- Loop counts: **1, 2, 3, 4, 5, 6**. 6 is beyond the training range; llama.cpp refuses 7.
- Decoding: temperature 0, one sample per item. `reasoning_effort` is passed through the chat template.
- Feasibility runs (kernels `ht-inkling-loops-smoke`, `-smoke2`) used three throwaway prompts. These prompts are not in any test set below.

## Questions (fixed now)
1. **Silent arithmetic (main question).** With `reasoning_effort = "none"`, does accuracy on multi-step arithmetic rise with loop count?
2. **Memory.** With `reasoning_effort = "none"`, does recall of 8 facts hidden in ~2,500 tokens of filler rise with loop count?
3. **Replication.** On GPQA Diamond (all 198 questions) with `reasoning_effort = "low"`, does accuracy follow the model card's shape (a big rise from 1 to 3 passes, then flat)? The card's numbers: 69.6 / 79.2 / 84.2 / 81.9 / 83.1% for 1-5 passes; its settings are not stated, so only the shape is compared.
4. **Visible vs silent.** In the GPQA runs, does the number of visible reasoning tokens change with loop count?

## Test sets (generated by `exp.py` from seed 20261122; files saved with every run)
- **Arithmetic:** 300 items, 100 each of: 2-digit × 2-digit, 3-digit × 2-digit, and a three-step expression `a × b + c × d` (2-digit operands). Prompt: "What is <expression>? Reply with just the number." Correct = the last integer in the reply equals the true value.
- **Memory:** 100 items. Each is ~2,500 tokens of seeded filler sentences with 8 facts "The code for locker <L> is <4 digits>." at random positions. The question asks for the codes of all 8 lockers, one per line. Score = fraction of the 8 codes reported correctly (exact 4-digit match next to the right locker).
- **GPQA Diamond:** 198 questions; answer options shuffled per question with the seed. Prompt ends "Answer with the letter only." Correct = the first standalone A-D letter in the final answer. `max_tokens` 3,072; a reply cut off without an answer counts as wrong and is reported as truncated. The questions are never published (dataset terms); only scores are.

## Measures and analysis (fixed now)
- Accuracy per loop count with 95% Wilson intervals. Arithmetic is also broken down by type.
- Visible reasoning: generated tokens minus answer tokens (from `timings.predicted_n`), plus characters of `reasoning_content`. Report the mean and median per loop count.
- Speed: tokens per second per loop count.
- Everything is reported, including truncations and failed requests. No question is dropped after seeing results.
- A difference between two loop counts is called "real" only if the 95% intervals don't overlap, or with a paired exact McNemar test (p < 0.05) on the same items. Otherwise it is "no clear difference".
